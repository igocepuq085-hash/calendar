# Производственный календарь

FastAPI-сервис для контроля допуска работников и выдачи одной персональной ICS-ссылки календаря на каждого работника:

```text
GET /cal/{token}.ics
```

Внутри одной ссылки собираются рабочие смены, проверки знаний, инструктажи, медкомиссии и фильтр. У администратора есть отдельная общая ICS-ссылка:

```text
GET /cal/admin/{token}.ics
```

В админский календарь попадают только события допуска всех активных работников. Рабочий график туда не добавляется.

## Текущий контекст продукта

- Название в интерфейсе: `Производственный календарь`.
- Один работник = одна персональная ссылка `/cal/{token}.ics`.
- Персональная ссылка содержит все события работника в одном календаре.
- Админская ссылка `/cal/admin/{token}.ics` содержит события допуска всех активных работников без смен.
- Рабочие смены в ICS отображаются как событие начала смены на один день, без `DTEND`, чтобы ночные смены не растягивались на два дня в мобильных календарях.
- Время смен фиксируется в `Asia/Yekaterinburg`: дневная смена начинается в 08:00, ночная в 20:00.
- Для обновления календарей используются стабильные `UID`, `LAST-MODIFIED`, `SEQUENCE` и no-cache заголовки.
- После ручного изменения дат создается короткое уведомление в персональном календаре примерно через 55 минут, чтобы мобильный календарь успел обновиться.
- В UI есть страховка от человеческого фактора: при изменении дат появляется плашка `Есть несохраненные изменения` с кнопкой `Сохранить все изменения`.
- Страница входа сделана без JS-зависимости, чтобы корректно работать на мобильных браузерах Honor/Android.

## Админка

Основные разделы:

- Главная панель.
- Работники.
- График смен.
- Проверка знаний.
- Медкомиссии.
- Архив.
- Загрузка файлов.
- Уведомления.
- Ошибки импорта.

Главная панель показывает:

- Проверки знаний текущего месяца.
- Медкомиссии.
- Общее число людей в подразделении.
- Число людей с допуском и прогресс к цели 100%.
- Проверки ближайшей недели.
- Проверки текущего месяца.

Строки событий на главной кликабельны: нажатие по работнику открывает его карточку. На странице работников есть быстрый поиск по ФИО, табельному номеру, должности, подразделению и ближайшему событию.

## Карточка работника

В карточке работника доступны:

- ФИО.
- Табельный номер.
- Подразделение.
- Должность.
- Статус: активный или неактивный.
- Персональная ICS-ссылка.
- Перевыпуск ссылки.
- Перенос работника в архив.
- Ручное изменение дат проверок, инструктажей и медкомиссий.
- Ближайшие смены.
- Подсветка дат красным, желтым и зеленым.

Рабочий график меняется только загрузкой Excel-файла. Ручные изменения касаются событий допуска и обязательно требуют сохранения.

Архивные работники скрыты из рабочих списков, календарей и общего учета. Вернуть работника в активный состав можно только со страницы архива.

## Уведомления ICS

Настройки уведомлений:

- Проверки знаний по ОТ, ЭБ, стропальщики, крановщики, работы на высоте: за 14 дней и за 1 день.
- Инструктажи: за 7 дней и за 1 день.
- Медкомиссия и фильтр: за 1 месяц и за 1 день.

При изменении графика или дат сервис обновляет существующие события по стабильным UID, а не создает новые поверх старых.

## Excel-импорт

Импорт двухэтапный:

1. Загрузка и предпросмотр.
2. Подтверждение импорта.

До подтверждения данные в базу не записываются. В предпросмотре показываются найденные строки, работники, события и ошибки распознавания.

Парсеры:

- `parser_work_schedule.py`
- `parser_knowledge.py`
- `parser_medical.py`

Excel-файлы могут содержать объединенные ячейки, даты в шапке, ФИО в строках и отметки смен в ячейках.

## Локальный запуск

```bash
python -m venv .venv
. .venv/Scripts/activate
pip install -e ".[dev]"
copy .env.example .env
alembic upgrade head
uvicorn app.main:app --reload
```

Для PostgreSQL укажите `DATABASE_URL`. Для быстрой локальной проверки можно оставить SQLite из `.env.example`.

## Railway deploy

1. Создайте сервис из репозитория.
2. Добавьте PostgreSQL plugin.
3. Укажите переменные:
   - `DATABASE_URL` - Railway подставит автоматически из PostgreSQL.
   - `SECRET_KEY` - длинная случайная строка.
   - `ADMIN_USERNAME` - логин администратора.
   - `ADMIN_PASSWORD` - пароль администратора.
   - `ADMIN_CALENDAR_TOKEN` - необязательный токен общей админской ICS-ссылки. Если пусто, сервис создаст стабильный токен из `SECRET_KEY`.
   - `BASE_URL` - публичный URL сервиса, например `https://example.up.railway.app`.
4. Railway использует `Dockerfile`, при старте выполняет `alembic upgrade head`.

## Основные маршруты

- `GET /health` - проверка живости.
- `GET /admin` - главная панель администратора.
- `GET /admin/login`, `POST /admin/login` - вход.
- `GET /admin/employees` - работники.
- `GET /admin/employees/{id}` - карточка работника.
- `POST /admin/employees/{id}/rotate-token` - перевыпустить персональную ссылку.
- `GET /admin/uploads` - загрузка Excel.
- `POST /admin/uploads/preview` - предпросмотр без записи событий в БД.
- `POST /admin/uploads/{id}/confirm` - подтверждение импорта.
- `GET /cal/{token}.ics` - персональный календарь работника.
- `GET /cal/admin/{token}.ics` - общий календарь администратора по всем активным работникам без рабочего графика.

- `app/routers/` - публичные и админские маршруты.
- `tests/` - проверки ключевых бизнес-правил.
